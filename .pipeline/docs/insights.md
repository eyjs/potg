## 1. 서드파티 쿠키 차단 — "신규 환경에서만 재현"의 정체
로그인 무한 새로고침은 오래 미스터리처럼 보였지만, 재현 조건("새 브라우저/시크릿 모드/새 프로필에서만")이 핵심 단서였다. 프론트(`potg-psi.vercel.app`)와 백엔드(`potg.joonbi.co.kr`)가 서로 다른 eTLD+1이라 인증 쿠키는 구조적으로 서드파티 쿠키였고, `SameSite=None; Secure`를 붙여도 Chrome 시크릿/새 프로필, Safari ITP, Firefox ETP는 기본적으로 차단한다. 즉 버그가 아니라 브라우저의 정상적인 프라이버시 정책과 우리 인증 설계의 충돌이었다.

**교훈**: "특정 환경에서만 재현"이라는 리포트는 그 환경의 차이(쿠키 정책, 익스텐션, 네트워크)를 먼저 의심해야 한다. 근본 해결은 프론트/백엔드 도메인 통일(same-site)이지만 인프라 변경이 필요해 이번엔 보류하고, Authorization 헤더 폴백이라는 애플리케이션 레벨 완화책을 택했다. **완화책과 근본 해결책을 구분해 문서화**해두면(이번엔 ADR-001과 컨트롤러 주석에 남김) 나중에 인프라 변경 시점에 왜 이 코드가 존재하는지 알 수 있다.

## 2. html-to-image의 cross-origin stylesheet 함정
`toPng()`는 캡처 시 `document.styleSheets`를 순회하며 각 스타일시트의 `cssRules`를 읽어 폰트/스타일을 임베딩하려 시도한다. 문제는 브라우저 확장 프로그램이 주입한 스타일시트나 외부 CDN에서 로드된 cross-origin stylesheet는 CORS 정책상 `cssRules` 접근 시 `SecurityError`를 던진다는 점이다. 이 예외가 한 스타일시트에서만 발생해도 **캡처 전체가 실패**로 끝난다 — 부분 실패가 아니라 전면 실패라 원인을 좁히기 어려웠다.

`skipFonts: true`(또는 `fontEmbedCSS: ''`)를 주면 이 순회 자체를 건너뛰어 문제 경로를 원천 차단한다. 트레이드오프는 캡처 이미지의 폰트가 시스템 기본으로 대체될 수 있다는 것인데, 이번 포스터는 인라인 스타일 기반이라 시각 차이가 크지 않았다.

**교훈**: 캡처 라이브러리 실패는 `catch(error)`에서 실제 `error` 객체를 로깅하지 않으면 원인 추적이 사실상 불가능하다. "에러 삼키지 않기" 규칙이 진단 속도에 직결된 실사례. 또한 `document.fonts.ready`(폰트 로딩 대기)와 `skipFonts`(폰트 임베딩 스킵)는 목적이 다르므로 둘 다 유지해도 무해하다 — 전자는 레이아웃 안정화, 후자는 크로스 오리진 예외 차단.

## 3. AudioContext 모바일 unlock 패턴
모바일 브라우저(iOS Safari, Chrome for Android)는 사용자 제스처 없이 오디오 재생을 차단한다. 이번 구현은 `pointerdown`/`touchstart`를 `{ once: true }`로 등록해 최초 제스처 시점에 `AudioContext.resume()`을 호출하는 표준 패턴을 사용했다. unlock 전 재생 시도는 예외가 아니라 "무음이 정상"으로 처리해야 하며, `.catch(() => {})`로 조용히 무시하되 이는 의도된 예외적 무시(에러 삼킴 규칙의 예외 케이스)로 명시해야 한다.

기존에 `current-player-card.tsx`가 `stageEvent.seq` 증가를 감지해 셀레브레이션 애니메이션을 트리거하던 패턴을 그대로 재사용해, 신규 소켓 이벤트나 상태를 추가하지 않고도 낙찰/유찰 효과음을 배선할 수 있었다.

**교훈**: 이미 검증된 상태 추적 패턴(seq 기반 1회성 트리거)이 있다면 새 이벤트 채널을 만들지 말고 재사용하라 — 병렬 구현 시 파일 충돌도 줄이고 리뷰 부담도 낮아진다.

## 4. `hidden lg:grid` / `lg:hidden` — 최소 침습 반응형 분기 기법
데스크톱 12-col 그리드가 모바일에서 그대로 압축되어 무너지는 문제를, 그리드 내부 구조를 반응형으로 뜯어고치는 대신 **그리드 자체를 breakpoint로 격리**하는 방식으로 풀었다.
```
grid grid-cols-12 gap-4          →  hidden lg:grid grid-cols-12 gap-4   (데스크톱 전용, 내부 그대로)
(형제 위치에 신규 추가)          →  lg:hidden ...                         (모바일 전용 블록)
```
데스크톱 내부 JSX는 한 글자도 건드리지 않아 회귀 위험이 0에 가깝고, 모바일 블록은 완전히 새로 작성해 자유도가 높다. 두 블록이 같은 데이터 소스(`roomState`, `chatMessages` 등)를 공유하므로 신규 prop이나 소켓 로직도 필요 없었다.

**교훈**: 기존 레이아웃을 반응형으로 "고치려" 하지 말고, 브레이크포인트로 완전히 분기해 병렬 렌더 트리를 만드는 편이 회귀 위험과 리뷰 난이도를 동시에 낮춘다. 특히 리스킨/레이아웃 대수술이 부담스러운 안정된 화면에 유용한 기법.
